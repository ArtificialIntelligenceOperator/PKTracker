# Новый стат PKTracker

Стат — это дробь `hits / cases` над точками решения или фактами руки. Хранится в базе, код менять не нужно.

## 1. Понять знаменатель

Сначала сформулируй словами, **когда возникает возможность** совершить действие. Это и есть `opportunity`, и именно
в нём делают ошибки: «CBet флопа» считается от рук, где игрок был префлоп-агрессором и увидел флоп без ставки перед
ним, а не от всех флопов.

Прочитай `docs/STATS.md` (или ресурс `pktracker://docs/stats`) — там все доступные поля с их смыслом,
и посмотри похожие встроенные статы: `list_stat_definitions` через MCP или вкладка «Статы» в приложении.

## 2. Написать определение

```json
{
  "code": "xr_turn",
  "title": "XR T",
  "scope": "decision",
  "opportunity": "Street == \"Turn\" && Facing == \"Bet\" && CheckedThisStreet",
  "hit": "Chosen == \"Raise\"",
  "colors": [ { "from": 0, "to": 10, "color": "#4FC3F7" }, { "from": 10, "to": 101, "color": "#EF5350" } ],
  "minSample": 30
}
```

`scope`: `decision` — частота действия в конкретной точке; `hand` — один раз на раздачу (VPIP, WTSD, выигрыш);
`expression` — формула над агрегатами других статов (`code.hits`, `code.cases`, `code.sum`, `max()`, `min()`).

## 3. Проверить на реальных раздачах

Через MCP — `test_stat`; в приложении — вкладка «Статы» → «Проверить и прогнать по 1000 рукам».

- `cases = 0` — условие никогда не выполняется, в нём ошибка.
- Доля сильно отличается от ожидаемой — проверь, не попали ли в знаменатель лишние ситуации
  (например, споты, где действия физически не было).

Сравни с близким встроенным статом на тех же данных: если «фолд на 3-бет» у тебя вышел 95%, скорее всего
в знаменатель попали чужие споты.

## 4. Сохранить и показать

`save_stat` (MCP) или «Сохранить и пересчитать» — пересчитывается только этот стат, остальные не трогаются.
Затем в HUD: `set_hud_profile` или вкладка HUD → «Профиль HUD» (`|` — перенос строки в панели).

## 5. Убедиться, что данные не разъехались

```powershell
dotnet run --project src/PKTracker.Cli -- check-agg
```

Агрегаты должны совпадать с пересчётом по `hand_decisions` / `hand_players`.
