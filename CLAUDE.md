# PKTracker — инструкции для агента

Покерный трекер и HUD для сети WPN (PokerKing, ACR, Black Chip, True Poker). C# / .NET 10, WPF, PostgreSQL.
Архитектура и правила, которые нельзя нарушать, — ниже; подробности по темам — в `docs/`.
Ссылки вида «§5.2» в комментариях кода — на исходный проектный план; сам план не опубликован,
поэтому комментарий рядом с такой ссылкой всегда объясняет причину словами и самодостаточен.

## Сборка и проверки

```powershell
dotnet build PKTracker.sln
dotnet test tests/PKTracker.Tests                       # должно быть зелено полностью
dotnet run --project src/PKTracker.Cli -- verify handHistory   # 0 ошибок парсера, 0 нарушений инвариантов
dotnet run --project src/PKTracker.Cli -- check-agg            # агрегаты == пересчёт по normalized
dotnet run --project src/PKTracker.Cli -- hud-check mtt        # все вкладки раскладки считаются, нет статов с cases=0
dotnet run --project src/PKTracker.Cli -- report mtt           # разбивки отчёта сходятся с итогом
python tools/mcp_smoke_test.py                          # MCP-сервер отвечает по протоколу
```

Тесты, которым нужна папка с историей, сами пропускаются, если её нет. Тестам **не нужна** база PostgreSQL.

## Структура

| Проект | Ответственность |
|---|---|
| `PKTracker.Core` | Канонические модели: `ParsedHand`, карты, enum-ы, битовые маски, `IHandHistoryParser`. Зависимостей нет |
| `PKTracker.Parsers` | Всё, что специфично для рума. Новый рум = новый класс здесь и ноль правок выше |
| `PKTracker.Engine` | Позиции, `HandContextBuilder` (деньги, `DecisionPoint`, `HandPlayerFacts`), эвалюатор, All-in EV, ICM, статы, инварианты |
| `PKTracker.Data` | PostgreSQL: миграции, импорт, агрегаты, отчёты, ребилды, попапы, ликфайндер, анонимизация |
| `PKTracker.Live` | Декодер `.data` — только рассадка |
| `PKTracker.App` | WPF: дашборд, HUD-оверлей, реплеер, редакторы |
| `PKTracker.Mcp` | MCP-сервер для Claude |
| `PKTracker.Cli` | Консольные команды |
| `tools/PKTracker.FakeTable` | Симулятор столов: проверка HUD без клиента рума |

Золотое правило: уровни выше парсера не знают, из какого рума пришла раздача.

## Правила, которые нельзя нарушать

Это не стиль, а вещи, которые уже ломались и стоят дорого:

1. **По умолчанию — только свои раздачи.** Импортируются раздачи, где за столом сидит Hero; файл без Hero
   отклоняется целиком. Датамайнинг и обмен базами — прямой запрет румов, поэтому раздачи без Hero принимает
   только ручной импорт и только после явного включения игроком (`TrackerSettings.ImportObservedHands`,
   `HandImporter.AllowObserved`, в консоли `import --observed`) — на его риск. Авто-импорт их не берёт никогда,
   значение по умолчанию не менять.
2. **Никакой подсказки в реальном времени.** Статы считаются только по завершённым раздачам. `.data`-канал клиента
   используется исключительно для рассадки; карты и эквити текущей руки не читаются. Инструменты анализа MCP
   (`TrackerContext.AnalysisHostAsync`) не отвечают, пока запущен клиент рума: ИИ-ассистент во время сессии — это RTA.
   Новый инструмент, отдающий данные об игроках или раздачах, берёт базу через `AnalysisHostAsync`, а не `HostAsync`.
3. **Деньги — `long` в сотых.** Никогда `double`, никогда парсинг с текущей культурой. Турнирные фишки и доллары
   не смешиваются в одном показателе.
4. **Биты в `fact_bits` / `ctx_bits` только добавляются в конец.** Переназначение бита тихо портит историю.
   Изменилась семантика — новый бит, `ContextVersion++`, полный ребилд. Новая колонка в `hand_decisions`
   заполняется только `rebuild --full` (из текста раздачи), а не селективным ребилдом: до него статы
   считаются по DEFAULT колонки и молча врут. Приложение предупреждает об этом в логе на старте.
5. **Неизвестная строка в парсере = отклонение раздачи** с текстом в `import_error`. Молчаливый пропуск недопустим.
6. **Инварианты обязаны быть зелёными**: деньги (`Σ вложено == банк + рейк + сборы`, `Σ выиграно == банк`) и позиции
   (ровно один BB, ≤ 1 SB и BTN, позиции не повторяются) — на каждой раздаче корпуса.
7. **Знаменатель важнее числителя.** Новый стат — это в первую очередь корректный `opportunity`. Всегда прогоняйте
   `test_stat`: `cases = 0` — ошибка в условии.
8. **UI не ходит в базу.** Все запросы — через `Task.Run`, HUD и отчёты используют разные пулы соединений.
9. **Хук окон (`SetWinEventHook`) ставится только из UI-потока.** Из фонового он молча не сработает.
10. **Позиции не считаются арифметикой от кнопки.** Только порядок действий: мёртвая кнопка, отсутствие SB и хедз-ап
    ломают «кнопка + 1 = SB».

## Частые задачи

- **Сверка статов с другим трекером** — `cli lab <папка> --hero <ник> --pack <пакет> --page <вкладка>`
  (считает по файлам, без базы) или `--opp/--hit/--group` для разового стата. Личные пакеты HUD и метки —
  в `private/` (в `.gitignore`) и в `%APPDATA%\PKTracker`, в репозиторий не попадают.
- **Правила румов для HUD** — `docs/ROOM_RULES.md` (с датой сверки и источниками), `RoomHudPolicy` и `RoomClientProbe`
  в `src/PKTracker.Data/RoomRules.cs`. На «статичных» румах раскладку перед показом над столом чистит
  `src/PKTracker.Engine/Hud/HudCompliance.cs`: новое свойство `DecisionPoint` / `HandPlayerFacts`, зависящее от карт,
  нужно добавить в его список, иначе стат по картам попадёт в HUD там, где это запрещено. Сеть GG запрещает и оверлей,
  и сторонний импорт, и сторонний софт рядом с клиентом (`NoCoexistence`, `ImportNeedsOptIn`). Что делать, пока открыт клиент GG,
  выбирает игрок — `TrackerSettings.WhenGgRunning` (`AppServices.ApplyGgModeAsync`): работать как обычно, выключить всё,
  что работает со столами (`HudManager.Suspended`, `.data`-канал, виджет сессии), или закрыть трекер вместе с MCP-сервером
  (`GgCoexistenceWatch`). Новый оверлей или живой источник данных обязан выключаться во втором режиме. Ничего, относящегося
  к GG, трекер при открытом клиенте не делает ни в одном режиме и от проверки процессов не прячется: маскировку процесса,
  окон или имён не добавлять.
- **Аналитика** — вкладка `src/PKTracker.App/Views/AnalyticsView.cs`, запросы `src/PKTracker.Data/AnalyticsRepository.cs`;
  класс готовой руки — `src/PKTracker.Engine/MadeHand.cs` (колонка `hand_decisions.made_hand`).
- **Проверка интерфейса без стола** — `PKTracker.exe --preview <ник> [группа/вкладка] [код стата]` и `--tab <вкладка>`.

- **Ручной импорт** — `src/PKTracker.Data/Import/FileImporter.cs` (папки, файлы, архивы; рум — по содержимому файла)
  и `ImportSources.cs` (чтение `.zip`/`.rar`/`.7z` в память). Вкладка — `src/PKTracker.App/MainWindow.Import.cs`.
  Проверка без кликов: `PKTracker.exe --import <путь>`. Базы на сервере — `src/PKTracker.Data/DatabaseCatalog.cs`.
- **Новый рум** — `docs/ADDING_A_ROOM.md`.
- **Новый стат** — `docs/STATS.md`; хранится в базе, код менять не нужно. Разрез по позиции, стеку
  или числу игроков — это фильтр ячейки раскладки, а не новый стат.
- **Раскладка HUD / попапы** — `docs/HUD_LAYOUTS.md`; правится редактором, лежит в `%APPDATA%\PKTracker\hud`.
  После правки прогнать `dotnet run --project src/PKTracker.Cli -- hud-check mtt`.
- **Отчёты срезами** — `docs/REPORTS.md`; вкладка «Отчёты», `src/PKTracker.Data/SliceReportRepository.cs`
  и `src/PKTracker.App/Views/ReportsView.cs`. После правок прогнать
  `dotnet run --project src/PKTracker.Cli -- report mtt`: он сверяет, что сумма групп равна итогу.
- **Схема базы и SQL** — `docs/DATABASE.md`. Изменение схемы = новая миграция `NNN_*.sql`, старые не редактируются.
- **Попапы HUD** — `docs/HUD_LAYOUTS.md`, раздел «Два уровня попапов». Ячейка панели открывает
  только привязанную к ней вкладку; ячейка внутри попапа — разбивку своего стата. Режим
  (наведение/клик) один на всё приложение, из `TrackerSettings.PopupTrigger`.
- **HUD** — `src/PKTracker.App/Hud`. Проверять на симуляторе столов:
  `tools\PKTracker.FakeTable\bin\Debug\net10.0-windows\PKTracker.FakeTable.exe "Los Banos:6:2" "Chubbuck:9:3:900,60"`,
  на вкладке «Настройки» временно указать процесс `PKTracker.FakeTable`, пустой класс окна и «Стол активен, часов» = 72
  (больше, если последняя раздача стола старше). Заголовок окна-симулятора должен совпадать со столом из базы: для турнира —
  `"Tournament <id> Table <номер>:8:5"`. Панели не рисуются над столом, перекрытым другим окном, — стол должен быть виден.
- **MCP-инструменты** — `src/PKTracker.Mcp/Tools`; после правок прогнать `tools/mcp_smoke_test.py`.

## Стиль

- Комментарии и сообщения интерфейса — на русском; код, коды статов и имена таблиц — на английском.
- Комментарий объясняет, **почему** так сделано (обычно — какая ловушка формата или правило рума за этим стоит),
  а не пересказывает код.
- Изменили поведение — обновите тест и, если это видно пользователю, `README.md`.
- Не коммитьте файлы истории рук, базы, дампы и `settings.json`: там ники других игроков и ваши пути.
