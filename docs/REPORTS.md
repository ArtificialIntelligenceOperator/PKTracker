# Отчёты: статистика срезами

Вкладка **Отчёты**: сверху карточка итогов и график, снизу разбивки, и по любой строке разбивки
можно провалиться внутрь.

```
Турниры ▾   [формат ✕] [BB ✕] [10–20bb ✕]                 1 234 рук · 56 турниров
─────────────────────────────────────────────────────────────────────────────────
Статы │ График
  56          42        31        +2.4        85
  Турниров    VPIP      PFR       bb/100      σ bb/100      …
─────────────────────────────────────────────────────────────────────────────────
Турниры │ Размеры стеков │ Позиции │ Месяцы │ Следующее действие │ Руки
  формат A     56   1 234   42  31  …
  формат Б      7     210   38  27  …
  Всего        63   1 444   41  30  …
```

## Срез

Срез — это набор активных фильтров; каждый показан «фишкой» сверху и снимается крестиком.
Двойной клик по строке разбивки добавляет соответствующую фишку:

| Вкладка | Что добавляет клик |
|---|---|
| Турниры | все турниры этого формата (в кеше вкладка называется «Лимиты» и по ней не режется) |
| Размеры стеков | полосу стека, `[от, до)` в bb |
| Позиции | позицию плюс число игроков: «хедз-ап» или «3+ игроков» — строки «BB» и «BB, хедз-ап» это разные споты, и клик обязан дать ровно ту строку, по которой кликнули |
| Следующее действие | раздачи, где вы приняли это решение (улица + против чего + что выбрали) |

Фильтры складываются: «формат + BB + 10–20bb + фолд против рейза» — законный срез,
и считается он одним запросом.

**Почему не второе окно рядом.** Распространённый приём — открывать по клику второй такой же
отчёт со сдвигом влево и сравнивать срезы рядом. Здесь клик пересчитывает тот же отчёт: строка
разбивки это полтора десятка колонок, и два окна рядом обрезают обе. Взамен фильтры
комбинируются между собой, чего одним уровнем вложенности не сделать, а сравнение остаётся:
строка «Всего» внизу каждой таблицы — это родительский срез целиком.

## Откуда берутся числа

Два источника, и они не смешиваются:

| | Источник | Что даёт |
|---|---|---|
| Статистика | `hand_players` / `hand_decisions` | руки, VPIP, PFR, 3Bet, WTSD, W$SD, WWSF, AF, AGG, bb/100, EV, σ |
| Деньги | `tournament` / `tournament_result` (из `.ots`) | турниров, входов, ITM, затраты, призы, профит, ROI, ABI |

Отсюда важное ограничение: **бай-ин, приз и ROI — свойство турнира целиком**. Когда в срезе
есть фильтр по позиции, стеку или действию, деньги всё равно показаны по турнирам среза без
этих фильтров — отчёт пишет об этом строкой под фишками. Резать деньги руками нельзя: половина
турнира не стоит половину бай-ина.

Турнирные фишки и доллары тоже не смешиваются (§3 `CLAUDE.md`): колонка «Итог» в турнирах —
фишки, в кеше — доллары, а график всегда в bb.

## Определения

Знаменатель у каждого показателя тот же, что у одноимённого стата в `docs/STATS.md`, — отчёт
и HUD обязаны показывать одно число:

| Показатель | Числитель / знаменатель |
|---|---|
| VPIP, PFR | добровольно вложил / раздач без бомб-пота |
| 3Bet | рейз / префлоп, `BetLevel==2`, против рейза |
| WTSD | дошёл до шоудауна / видел флоп |
| W$SD | выиграл на шоудауне / дошёл до шоудауна |
| WWSF | выиграл раздачу **и видел флоп** / видел флоп |
| AF | (ставки + рейзы) / коллы, постфлоп |
| AGG % | (ставки + рейзы) / (ставки + рейзы + коллы + фолды), постфлоп |
| σ bb/100 | стандартное отклонение одной раздачи × 10 (общепринятая формула) |
| Удача, bb/100 | факт − All-in EV |
| ITM | приз или билет > 0 / входов (баунти не считается: в PKO они капают и вне призов) |
| ABI | затраты / входов |

Дисперсия хранится суммами `(n, Σx, Σx²)`, поэтому строка «Всего» складывается из строк
разбивки и совпадает с отдельным пересчётом по всей выборке — это проверяется тестом.

### Почему VPIP и PFR могут не сойтись с другим трекером

На одних и тех же раздачах разные программы показывают разные проценты, и это обычно не ошибка
ни у кого — расходятся **знаменатели**.

PKTracker считает VPIP и PFR от **всех розданных раздач**. Часть трекеров выбрасывает из
знаменателя раздачи, где игрок вообще не получил хода: всем сбросили до BB («walk») или BB был
в олл-ине блайндом. Скажем, из 1000 розданных раздач ход был в 900 — и один и тот же числитель
даёт заметно разные проценты в зависимости от выбора знаменателя. Для PFR разница бывает ещё больше: можно
дополнительно выбрасывать споты, где рейз был невозможен (перед игроком олл-ин).

Знаменатель здесь общий со статом `vpip` в HUD намеренно: один и тот же показатель не должен
означать в окне отчёта одно, а над столом другое. Точные определения — в таблице выше и
в `docs/STATS.md`.

## Чего нет

Не воспроизведены две вещи, которые есть в некоторых трекерах: разбор **диапазона префлоп**
по вскрытым картам оппонентов и **детальная сила руки** (TPTK, гатшот, Draw+Pair и прочее).
Первое требует вскрытых карт, которых на большинстве раздач просто нет; для второго у нас
в `hand_decisions.hand_strength` лежит только категория комбинации (пара, две пары, сет…).
Категорийная разбивка уже есть в попапе стата — вкладка «Сила руки» (`StatDetailWindow`).

## Проверка

Отчёт целиком прогоняется из консоли — это же и способ поймать разъехавшийся `WHERE`:

```powershell
dotnet run --project src/PKTracker.Cli -- report mtt                    # итог + все разбивки
dotnet run --project src/PKTracker.Cli -- report mtt --drill "Spin"     # то же по одному формату
dotnet run --project src/PKTracker.Cli -- report cash
```

Команда печатает итог и каждую разбивку, после чего проверяет три вещи:

- сумма групп равна итогу;
- число точек графика равно числу раздач;
- **клик по строке даёт ровно её числа** — для каждой строки «Позиции», «Размеры стеков» и
  «Следующее действие» срез пересчитывается с соответствующим фильтром и сверяется со строкой.

Последняя проверка и есть главная: именно она ловит расхождение условия среза с ключом
группировки, которое в окне видно только как «странные числа». Строка `РАСХОЖДЕНИЕ` в выводе —
это ошибка, команда возвращает ненулевой код.
