# Раскладки HUD: панель и попапы

HUD PKTracker устроен привычно: над местом игрока висит маленькая **панель**, а её ячейки
открывают **попап** — окно со вкладками, где та же статистика разрезана по позициям, полосам
стека и числу игроков. Наведение на ячейку внутри попапа открывает третье окно — разбивку
одного стата.

Всё это описывается одним **профилем** — JSON-файлом в `%APPDATA%\PKTracker\hud\<имя>.json`.
Правится профиль визуально: вкладка **HUD → Редактор HUD и попапов**.

## Из чего состоит профиль

```
Профиль (HudProfile)
├── Panel  — страница, которая висит над местом игрока
└── Pages  — вкладки попапа: GENERAL, R3, 3 BET, DYNAMIC, SQZ, RAISER IP, …
```

Страница (`HudPage`) — одна большая сетка. Ячейка (`HudCell`) стоит в клетке `(Row, Col)`, может
занимать несколько клеток (`RowSpan`, `ColSpan`) и бывает двух видов:

- **подпись** — только `Text`, без стата (заголовки колонок, названия строк);
- **значение** — код стата плюс необязательный **фильтр**.

## Вкладки панели, группы попапа, пакеты

- **Вкладки панели** — `panelTabs` профиля: несколько страниц, над столом видна одна, переключение буквами
  слева (P / B / C / V…). Выбранная вкладка запоминается для новых панелей. Автопереключения по ходу раздачи
  нет намеренно: «динамический» HUD запрещён правилами iPoker и Winamax.
- **Группы попапа** — поле `group` у вкладки: слева в попапе список групп, сверху вкладки группы. Ячейка панели
  ссылается на вкладку как «группа/вкладка» (или просто именем, если оно уникально). Поле `note` — подсказка
  под вкладками (условия, стеки).
- **Рамка ячейки** — `style.border` (`#RRGGBB`): так удобно помечать ячейки, открывающие попап.
- **Привязка попапов** — «HUD → Привязка попапов…»: таблица всех ячеек всех вкладок панели с выбором вкладки
  попапа; кнопка «непривязанным — как у соседа слева» заполняет пропуски. В редакторе то же поле — выпадающий
  список, а не ввод имени: опечатка тихо отвязала бы ячейку.
- **Пакет HUD** — файл `*.hudpack.json` `{ name, profile, stats[] }`: раскладка вместе с определениями статов.
  Импорт («HUD → Импорт пакета HUD…» или `cli hud-import`) сохраняет статы в базу (неизменившиеся не трогает),
  профиль — в `%APPDATA%\PKTracker\hud` и досчитывает агрегаты новых статов. Личные пакеты держите вне
  репозитория (папка `private/` в `.gitignore`).
- **Вид значений** («Настройки»): выборка меньше N — мелкой цифрой у значения («50₂», как в Hand2Note),
  «99 вместо 100».
- **Метки** — правый клик по панели без перетаскивания: цветовая метка (тип оппонента), подпись, заметка.
  На панели метка — цветной значок и название типа (или своя подпись).
- **Рамка группы** — соседние ячейки с одинаковым `style.border` обводятся общим контуром, а не каждая своим:
  так выделяются блоки («3-бет / фолд на 3-бет», строка RFI по позициям). Чтобы два соседних блока не слились,
  задайте им чуть разные цвета.
- **Пара 9max / 6max** — «HUD → 9max / 6max по столу»: если имя выбранной раскладки содержит «9max» и сохранена
  раскладка с тем же именем и «6max», столы до 6 мест получают вторую (и наоборот).
- **Цвет значения** — диапазоны `colors` стата: `[{"from": 0, "to": 18, "color": "#F06292"}, …]`.

Панель читает агрегаты, а в них нет позиции оппонента. Ячейки вроде «OOP f3b NA» (относительно 3-беттора)
заводятся отдельным статом с этим условием в `opportunity`.

## Фильтр — главная идея

Одна и та же статистика стоит в десятках ячеек, отличаясь только обстановкой. Заводить под
каждую ячейку отдельный стат — это сотни определений и сотни пересчётов. Поэтому ячейка ссылается
на общий стат и добавляет фильтр, который сужает его **знаменатель**:

| Поле | Смысл | Пример |
|---|---|---|
| `pos` | позиции самого игрока | `["CO","BTN"]` |
| `vsPos` | позиция последнего агрессора | `["BTN"]` — «BB vs BTN» |
| `openPos` | позиция открывшего банк рейзом | `["SB","BB"]` — сквиз против опена с блайндов |
| `playersMin` / `playersMax` | начальное количество игроков за столом | `2`/`2` — только хедз-ап |
| `inHandMin` / `inHandMax` | игроков, оставшихся в раздаче | `3`/`10` — «CB vs 2 players» |
| `stackMin` / `stackMax` | эффективный стек в bb, `[от, до)` | `11`/`15` |
| `toBbMin` / `toBbMax` | размер собственной ставки «до», bb | опен ≤ 4bb |
| `allIn` | действие олл-ин: `true` / `false` / не задано | колонки ALL-IN и NO ALL-IN |
| `ante` | раздачи с анте | колонки NO / ANTE на вкладке R3 |
| `where` | произвольное выражение на языке статов | `IsIp` |

Так, `3bet` из CO против BTN при 15–25bb без олл-ина — это одна ячейка со статом `three_bet`
и фильтром `pos=[CO], vsPos=[BTN], stackMin=15, stackMax=25, allIn=false`.

## Где фильтр работает, а где нет

Панель и попап берут данные из разных мест, и это ограничивает панель:

| | Источник | Что умеет фильтр |
|---|---|---|
| **Панель** | `player_stat_agg` (агрегаты) | позиция, число игроков, полосы стека по границам 10/20/40/100bb |
| **Попап** | `hand_decisions` / `hand_players` (normalized) | всё перечисленное выше без ограничений |

Причина — скорость: панель рисуется для девяти игроков на шести столах и обязана укладываться
в паузу между раздачами, а агрегат хранит всего три измерения. Попап открывается по одному игроку,
читает его раздачи один раз и держит их в памяти, пока открыт, — поэтому там доступно всё.

Если ячейке панели нужен разрез, которого нет в агрегате (позиция оппонента, точная полоса стека,
олл-ин), есть два пути: завести отдельный стат с этим условием в `opportunity` — или поставить
ячейку в попап. Редактор предупреждает об этом жёлтой строкой под свойствами ячейки.

## Два уровня попапов и чем они открываются

Попапы устроены в два уровня, и уровень задаёт, что именно откроется:

| Где курсор | Что откроется |
|---|---|
| ячейка **панели** над столом | вкладка попапа, **привязанная к этой ячейке** в редакторе |
| ячейка **внутри попапа** | разбивка этого стата: диапазоны по действиям, исходы спота, список рук |

Ячейка панели без привязанной вкладки не реагирует ни на клик, ни на наведение. Это сделано
намеренно: за столом курсор всё время ходит по панелям, и если бы каждая ячейка что-нибудь
открывала, HUD дёргался бы от любого движения мышью. Поле привязки — «Открывать вкладку»
в свойствах ячейки; редактор прямо пишет под ним, привязана вкладка или нет.

**Чем открывается** — настройка `Настройки → Попапы`:

- **по наведению** (по умолчанию, задержка 500 мс) — попап открывается, если курсор постоял
  на ячейке, и закрывается сам через 400 мс после того, как курсор ушёл и с ячейки, и с самого
  попапа. Переход курсора со стата на попап его не закрывает — иначе попап нельзя было бы
  пролистать;
- **по клику** — наведение не делает ничего, попап открывается кликом и висит, пока его
  не закроют. Повторный клик по той же ячейке закрывает.

Уровни живут отдельно: попап стата открывается **поверх** вкладки профиля и не закрывает её,
а курсор на попапе стата удерживает открытым и его, и вкладку под ним. Закрытие идёт сверху вниз.

В любом режиме попап можно **закрепить булавкой** (`📌` в углу): закреплённый не закрывается
сам и не мешает открыть следующий — наведение на другой стат откроет новое окно рядом.
Так сравнивают два спота.

Задержки настраиваются там же и относятся только к режиму наведения.

## Попап стата

То, что открывается при наведении на ячейку внутри попапа:

- **значение и выборка** стата у этого игрока;
- **исходы спота** — во что он обходится, а не только как часто случается: профит в bb на
  раздачу, доля выигранных раздач, WTSD и W$SD **среди раздач, где стат сработал**. Считаются
  по раздачам, а не по решениям: если стат сработал в раздаче дважды, её результат всё равно
  учитывается один раз;
- **вкладка на каждое действие** — «Рейз», «Колл», «Фолд»: сетка 13×13 с руками, которыми
  игрок выбрал именно это действие в этом споте. Раскладываются все возможности, а не только
  срабатывания, — смысл как раз в том, чтобы диапазон рейза и диапазон колла лежали рядом;
- разбивки по позициям и стеку, Next Actions, сайзинги, сила руки, текстуры бордов;
- список рук с переходом в реплеер по двойному клику.

Диапазоны собираются только из **вскрытых** карт — у оппонентов они известны лишь на шоудауне.

## Как двигать панели

- **правая кнопка мыши, зажатая в любом месте панели** — перетащить её. Левая занята попапами,
  а заголовок панели узкий, и попасть по нему над столом трудно;
- левая кнопка на заголовке панели — то же самое.

Работает и за столом, и в реплеере. За столом смещение запоминается по размеру стола
в `hud_layout.json`, в реплеере — по месту за столом в `settings.json` (`ReplayerPanelOffsets`):
панель мешает всегда в одном и том же месте, поэтому привязка к месту, а не к игроку.

## Редактор

**HUD → Редактор HUD и попапов.**

- Слева — список вкладок; `▣ Панель` — то, что видно над столом. Кнопки `+ вкладка` / `− вкладка`.
- По центру — сетка. Клик по ячейке выбирает её, клик по пустой клетке предлагает добавить новую.
  Вместо настоящих чисел показывается `99` — видно ширину, цвет и выравнивание.
- Справа — свойства: текст, стат, координаты, объединение клеток, цвета, фильтр.
- `Сохранить как…` создаёт файл в `%APPDATA%\PKTracker\hud`. Встроенные профили не перезаписываются:
  после обновления программы они останутся актуальными, а ваши правки — вашими.

Выбранный профиль задаётся на вкладке HUD в поле **Раскладка** — отдельно для кеша и турниров.

## Значок выбора раскладки

Мелкий значок `▤` — над каждым привязанным столом и в углу реплеера. Клик открывает список:
встроенная раскладка, ваши сохранённые, старый плоский список статов, «Скрыть HUD». Значок
перетаскивается мышью; и выбор, и положение запоминаются — для столов положение хранится
в `hud_layout.json` по размеру стола, для реплеера в `settings.json`.

При «Скрыть HUD» панели пропадают, а значок остаётся: иначе включить HUD обратно было бы нечем.

## HUD в реплеере

Реплеер показывает те же панели рядом с местами игроков, что были видны за столом, и открывает
тот же попап по тем же правилам (привязанная вкладка, наведение или клик). Цифры берутся из агрегатов — то есть это статистика игрока
**за всё время**, а не срез на момент раздачи. Выключается тем же значком или настройкой
`ReplayerHud` в `settings.json`.

## Проверка раскладки

Ошибка в раскладке тихая: ячейка с недостижимым условием просто рисует прочерк. Поэтому есть
консольная проверка, которая прогоняет все вкладки по настоящему игроку:

```powershell
dotnet run --project src/PKTracker.Cli -- hud-check mtt              # по Hero
dotnet run --project src/PKTracker.Cli -- hud-check cash --verbose   # с перечнем пустых ячеек
dotnet run --project src/PKTracker.Cli -- hud-check mtt --profile "Мой MTT" --player Villain_1234
```

Вывод показывает по каждой вкладке, сколько в ней ячеек со статом и сколько осталось без выборки.
Пустая ячейка — не всегда ошибка: редкий спот на маленьком корпусе честно пуст. Ошибка — когда
ячейка пуста при большой выборке: значит, условия стата и фильтра противоречат друг другу.

## Встроенные профили

**MTT** — 16 вкладок: `GENERAL`, `R3`, `3 BET`, `DYNAMIC`, `SQZ`,
`RAISER IP`, `RAISER OOP`, `CALLER IP`, `CALLER OOP`, `HU`, `LIT`, `STEALS`, `STEALS SHORT`,
`OP(HU)`, `3MAX`.

**Cash** — те же вкладки без пуш-фолдовых, с полосами стека под кеш: в кеше стек почти всегда около
сотни блайндов, и турнирные полосы 12–20bb там дали бы всегда пустые колонки.

Два отличия от оригинала, сделанных намеренно:

- колонки названы позициями PKTracker (`EP`, `MP`, `CO`, `BTN`, `SB`, `BB`), а не `LG` и `HJ`,
  как принято в некоторых трекерах: там «HJ» означает MP, и рядом с настоящим HJ это путало бы. `EP` = UTG/UTG+1/MP,
  `MP` = LJ/HJ;
- вкладки `Notes`, `RR`, `HT`, `HT2`, `HRC`, `SB`, `BTN` не воспроизведены — их содержимого
  в исходных скриншотах не было. Добавляются редактором без правок кода.

## Что понадобилось добавить в контекст раздачи

Часть ячеек опирается на то, чего в `hand_decisions` не было (ContextVersion 2, миграции 003 и 004):

| Поле | Зачем |
|---|---|
| `VsPosition` | позиция последнего агрессора — матрицы «BB vs BTN», «EP vs MP», «Fold vs DONK» |
| `OpenerPosition` | кто открыл банк — фильтр 4-бет-спотов и сквиза по опенрейзеру |
| `ToAmount` → `ToAmountBb` | размер собственной ставки в bb: «опен 3-5x», «R1 ≤ 4bb» |
| `FacingAmount` → `FacingBb`, `RaiseRatio` | во сколько раз рейз перекрывает ставку: минрейз против овербета |
| `LineBits` → `MyLine` | собственная линия на постфлопе (`BXB`, `XCF`) — блоки линий на вкладках IP/OOP |

Эти поля доступны в условиях статов наравне с остальными (см. `docs/STATS.md`).

**Важно:** значения появляются только после полного ребилда — они восстанавливаются из текста
раздачи, а не из уже разобранных строк. Пока он не сделан, программа пишет в лог предупреждение,
и статы, опирающиеся на эти поля, считаются по умолчаниям колонок:

```powershell
dotnet run --project src/PKTracker.Cli -- rebuild --full
```
