# Как добавить покерный рум

Архитектура рассчитана на это: всё, что специфично для рума, живёт в `PKTracker.Parsers`. Уровни выше (модель раздачи,
стат-движок, HUD, дашборд) про румы не знают. Добавление рума — это новый класс и тесты, без правок движка.

Есть два случая: **новый скин той же сети** (уже поддержан) и **новый формат hand history**.

## Случай 1: другой скин WPN

ACR, Black Chip Poker, True Poker используют тот же формат, что и PokerKing. Достаточно выбрать рум в настройках
(вкладка «Настройки» → «Рум») или запустить с `--room ACR`. Данные румов в базе не смешиваются.

Новый скин сети добавляется одной строкой в миграцию:

```sql
INSERT INTO room (room_id, code, network) VALUES (5, 'YOURSKIN', 'WPN') ON CONFLICT DO NOTHING;
```

## Случай 2: новый формат (PokerStars, GG, 888…)

### 1. Соберите корпус и изучите формат

Возьмите свои файлы истории и посмотрите, какие строки вообще встречаются — это надёжнее, чем писать парсер по памяти:

```bash
# все виды строк с заменой ников и сумм на заглушки, по убыванию частоты
python tools/scan_lines.py "C:\путь\к\истории"
```

Обратите особое внимание на ловушки, которые уже встретились в WPN (см. `PLAN.md` §0.6):
ники с пробелами и цифрами, Run It Twice, рейк в строках банка, мёртвые блайнды и посты вне очереди,
игроки без карт, `raises X to Y` (где X — не размер рейза), сайд-поты, анте, возврат непоколлированной ставки,
бомб-поты, мёртвая кнопка, хедз-ап, раздачи, где кто-то сидит, но не участвует.

### 2. Реализуйте `IHandHistoryParser`

`src/PKTracker.Parsers/<Room>/<Room>HandParser.cs`:

```csharp
public sealed class StarsHandParser : IHandHistoryParser
{
    public string RoomCode => "POKERSTARS";
    public bool CanParse(ReadOnlySpan<char> fileHead) => fileHead.StartsWith("PokerStars Hand #");
    // Как понять, что раздача в дописываемом файле закончена: с чего начинается заголовок и метка итогов.
    public HandBoundary Boundary { get; } = new(["PokerStars "], "*** SUMMARY ***");
    public IEnumerable<HandParseResult> Parse(string text, HandSourceInfo source, long baseOffset = 0) { ... }
}
```

Правила, без которых потом будет больно:

- **Модель `ParsedHand` — room-agnostic.** Никаких полей вроде `JpFee`: только `Rake` и словарь `ExtraFees`.
- **Суммы** — `long` в сотых (центы, фишки×100), через `decimal.Parse` с `InvariantCulture`. Никаких `double`.
- **Время** — `DateTime.ParseExact` с `AssumeUniversal | AdjustToUniversal`.
- **Ник резолвится по списку мест**, самым длинным совпадением, с проверкой глагола после ника. `Split(' ')` — нельзя:
  ники бывают с пробелами и бывают префиксами других ников.
- **Неизвестная строка — это ошибка**, а не повод промолчать: раздача отклоняется целиком и попадает в `import_error`.
  Молчаливый пропуск означает, что смена формата обнаружится через месяц по кривым статам.
- **Кто раздан** определяется по итоговой секции раздачи, а не по списку мест в шапке.
- **`raises X to Y`**: в разных румах X значит разное. Берите `Y` и считайте доплату как `Y − уже вложено на улице`.

### 3. Проверьте инварианты на своём корпусе

```powershell
dotnet run --project src\PKTracker.Cli -- verify "C:\путь\к\истории"
```

Должно быть: **0 ошибок парсера** и **0 нарушений инвариантов**. Проверяются:

- деньги: `Σ вложено == банк + рейк + сборы`, `Σ выиграно == банк`;
- позиции: ровно один BB, не больше одного SB и BTN, у всех раздававшихся позиция назначена, позиции не повторяются.

Инварианты считаются по каждой раздаче — если они зелёные на нескольких тысячах рук, парсер почти наверняка верен.

### 4. Тесты

В `tests/PKTracker.Tests` добавьте:

- разбор нескольких раздач-образцов с ловушками формата (как `SampleHands.cs`);
- проверку, что неизвестная строка отклоняет раздачу;
- прогон всего корпуса с инвариантами (как `CorpusTests`), если корпус есть локально.

**Не кладите в репозиторий свои файлы истории**: в них ники других игроков, а правила румов запрещают обмен базами.
Тесты должны пропускаться, если корпуса нет (см. `TestUtil.CorpusDir`).

### 5. Регистрация рума

1. Добавьте рум в новую миграцию `src/PKTracker.Data/Migrations/NNN_*.sql`.
2. Добавьте строку в `ParserRegistry.Entries` (`src/PKTracker.Parsers/ParserRegistry.cs`): код, сеть, подпись
   и фабрика парсера. Список румов в настройках, импорт, дозор и ребилд берут его оттуда.
3. Правила рума для HUD — `RoomHudPolicy` (`src/PKTracker.Data/RoomRules.cs`) и `docs/ROOM_RULES.md`.
4. Общие приёмы (суммы, карты, поиск ника, перевод времени в UTC, учёт ставок улицы) — `Parsers/Common`.
5. Проверка корпуса без базы: `tools/VerifyParsers <папка> [--only ROOM]`.
3. Если формат имени файла другой — свой `*FileNameParser` (тип игры и идентификаторы стола берутся из имени файла,
   потому что в тексте раздачи SNG и MTT часто неразличимы).

### 6. Турнирные итоги и live-канал (необязательно)

- Итоги турниров (призовые, место, баунти) в hand history обычно отсутствуют — нужен отдельный парсер файлов итогов,
  как `TournamentSummaryParser` для `.ots`. Без него турнирный P&L будет неверным.
- Если клиент пишет свой протокол (как `.data` у PokerKing), из него берут **только рассадку**: кто где сидит и какое
  место у вас. Карты, эквити и всё, что относится к текущей раздаче, читать нельзя — это запрещено правилами румов.

## Ловушки формата WPN

Замеченное на живом корпусе; каждая ловушка закрыта оракул-тестом в `PKTracker.Tests`.

- **Завышенный `Uncalled bet` в 3-max спинах.** Когда короткий стек в олл-ине за неполный блайнд,
  а обладатель большего блайнда сбрасывает, рум пишет в «Uncalled bet» не только непокрытую ставку,
  но и мёртвый сайд-пот, который агрессор забирает без вскрытия. Сумма выходит больше, чем игрок
  вообще поставил, и `invested` уходит в минус. `HandContextBuilder` ограничивает возврат
  превышением над самым большим вкладом тех, кто ещё в раздаче.
- **Блайнд меньше номинала.** `posts the big blind 5.00 and is all-in` при уровне 30/60 — обычное
  дело в спинах; уровень ставки на улице задаётся не номиналом блайнда, а фактически поставленным.
- **Бомб-поты без позиций.** Позиции не назначаются вовсе (`Position.None` у всех), `VsPosition`
  тоже пуст. Проверки «у всех есть позиция» обязаны исключать `HandFlags.BombPot`.
- **`.ots` не содержит названия и формата турнира** — только номер, бай-ин и места. Турнир,
  заведённый итогами раньше раздач, остаётся безымянным, пока импорт раздач не допишет имя.

## Чек-лист

- [ ] `CanParse` отличает формат по началу файла
- [ ] `Boundary` задаёт начало раздачи и метку итогов (для XML — закрывающий тег и `WholeFile`): без него
      импорт дописываемых файлов считает раздачи незавершёнными и молча ничего не берёт
- [ ] 0 ошибок и 0 нарушений инвариантов на своём корпусе (`verify`)
- [ ] тесты на ловушки формата
- [ ] рум добавлен в миграцию и в настройки
- [ ] свои файлы истории не попали в коммит
