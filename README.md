# PKTracker

Покерный трекер и HUD для сети **Winning Poker Network** (PokerKing, Americas Cardroom, Black Chip Poker, True Poker),
**PokerStars**, **Winamax**, **GGPoker / PokerOK**, **iPoker** и **888poker** с подключением **Claude через MCP**: агент читает вашу локальную базу, разбирает сыгранные раздачи, ищет лики,
создаёт статы и настраивает HUD.

C# / .NET 10 · WPF · PostgreSQL · открытый код (MIT).

> **English:** a poker tracker and HUD for the WPN network (PokerKing, ACR, Black Chip, True Poker) with an MCP server,
> so Claude can analyse your own hand database, build custom stats and configure the HUD. Docs are in Russian;
> the code, stat codes and database schema are in English. See `docs/MCP.md` and `CLAUDE.md`.

---

## Что умеет

**Трекер**
- Форматы истории: WPN, PokerStars (и клоны формата, например Chico), Winamax, GG/PokerOK, iPoker (XML), 888poker.
  Формат файла определяется по содержимому, имя файла не важно. Строгие парсеры: неизвестная строка
  отклоняет раздачу (см. `docs/ADDING_A_ROOM.md`).
- Парсер hand history WPN: кеш, MTT, SNG, Spins. Run It Twice, бомб-поты, мёртвая кнопка, хедз-ап, сайд-поты,
  анте, посты вне очереди, ники с пробелами и цифрами.
- Импорт в PostgreSQL: массовая загрузка, дозор папки (новые руки появляются в HUD по ходу игры), без дублей.
- Инварианты на каждой раздаче: деньги сходятся, позиции корректны.
- Турниры: итоги из `.ots`, ре-энтри, баунти, билеты, ROI, ITM. Загрузка истории турниров — кнопкой
  прямо во вкладке «Турниры», статистика раскладывается по форматам (бай-ин, MTT / SNG / Spin & Go, размер стола, PKO):
  сколько сыграно, у скольких есть раздачи, ITM, средний финиш, ROI, фишки, **Chip EV** и удача в олл-инах.
  Если итогов турнира нет, но рум пишет стоимость входа в заголовке раздачи («$5.00+$0.50 USD»), бай-ин и формат
  берутся оттуда; призы, место и ROI по-прежнему появляются только из итогов.
- График турниров — по раздачам, две линии (факт и Chip EV), с привычными фильтрами: формат,
  число игроков за столом (хедз-ап, трое), позиция Hero, глубина стека. Chip EV считается по hand history,
  поэтому у турниров без импортированных раздач он пуст — колонка «С раздачами» показывает, по скольким он вообще есть.

**Анализ**
- **Отчёты срезами**: карточка итогов и график сверху, разбивки снизу —
  по формату турнира, полосе стека, позиции (с отдельными строками хедз-апа), месяцу, следующему действию.
  Двойной клик по строке сужает срез и добавляет фишку в крошки; фильтры складываются между собой.
  См. `docs/REPORTS.md`.
- Дашборд: winrate, bb/100, график Net won / шоудаун / без шоудауна / **All-in EV**, сессии, позиции, лимиты.
  Сессии считаются и для кеша, и для турниров (итог турнирной сессии — в bb). Вид игры на вкладках при первом
  показе выбирается сам — тот, в котором у вас больше раздач.
- **All-in EV** (эквити по всем раскладам) и **Chip EV / $EV** для турниров (ICM для SNG).
  В Spin & Go (3 игрока, 100% первому) ICM линеен по стекам, поэтому $EV там не считается — только Chip EV.
- Попапы статов: позиции, глубина стека, Next Actions, сайзинги, сила руки, текстуры бордов, сетки рук 13×13.
- Ликфайндер: вы против пула из собственной базы, сортировка по значимости отклонения. Счётчики («Раздач»)
  с пулом не сравниваются, а строки с малой выборкой у вас или у пула помечены «мало данных» и не всплывают наверх.
- Вкладка «Игроки»: список открывается сразу (самые сыгранные оппоненты), статы игрока фильтруются по названию
  и по наличию выборки.
- Поиск рук выражением: `Pfr && SawShowdown && !WonAtShowdown`, `HoleClass == 0 && Position == "BB"`.
- Реплеер: пошаговый разбор раздачи, две доски при Run It Twice, панели HUD рядом с местами игроков.
- Мелкий перетаскиваемый значок над столом и в реплеере: выбор раскладки на лету, с запоминанием.
- **Цветовые метки и подписи** на игроков: свой каталог типов оппонентов в
  `%APPDATA%\PKTracker\markers.json`; метка и подпись видны на панели HUD, ставятся правым кликом по панели
  (без перетаскивания) или во вкладке «Игроки».

**HUD**
- Отдельное окно-панель на игрока: клики по столу проходят мимо панелей, фокус у стола не отбирается.
- Поворот стола по вашему месту, слежение за окнами, скрытие при перекрытии, поддержка нескольких мониторов и DPI.
- Два режима открытия попапов (настройка): **по наведению** через 0.5 с с автозакрытием
  или **по клику**. Любой попап закрепляется булавкой, чтобы сравнить два спота рядом.
- Попап стата: диапазоны 13×13 отдельно по каждому действию («чем рейзил» рядом с «чем коллировал»),
  исходы спота (профит bb/рука, выиграл руку, WTSD, W$SD), Next Actions, сайзинги, борды, список рук.
- Панель перетаскивается правой кнопкой мыши, зажатой в любом её месте, — и за столом, и в реплеере.
- Многоячеечные раскладки: панель-сетка над местом и попап со вкладками (GENERAL, 3 BET, STEALS, HU, …),
  где ячейка — это стат плюс фильтр: позиция, позиция оппонента, полоса стека, число игроков, олл-ин, анте.
  Встроено два профиля — турнирный (16 вкладок, ~950 ячеек) и кеш; см. `docs/HUD_LAYOUTS.md`.
- Визуальный редактор HUD и попапов: сетка, свойства ячейки, свои вкладки; горячая клавиша показа/скрытия.
- **Вкладки панели** (P / B / C / V…): над столом видна одна страница статов, переключение буквами сбоку.
- **Группы попапа**: слева список групп (по спотам), сверху вкладки группы — как в Hand2Note.
- **Привязка попапов** одной таблицей («HUD → Привязка попапов…»): какая ячейка панели какую вкладку открывает.
- **Пакеты HUD** (`*.hudpack.json`): раскладка вместе со своими статами; «HUD → Импорт пакета HUD…» или
  `cli hud-import`. Статы добавляются в базу и досчитываются.
- Вид статов как в Hand2Note: малая выборка мелкой цифрой («50₂»), 99 вместо 100, рамки ячеек.
- Учтены правила румов (`docs/ROOM_RULES.md`, сверено 11.11.2026): на PokerStars, iPoker, Winamax и 888 над столом
  остаётся только числовой HUD — диапазоны по вскрытым картам, статы по силе руки и текстуре борда скрываются,
  цвет значения ограничен тремя диапазонами; на PokerStars то же действует в реплеере, пока клиент открыт.
  Над столами GG оверлей не запускается.
- **Совместная игра с GG** («Настройки → Пока открыт клиент GG»). С 01.12.2026 GG запрещает любой сторонний покерный
  софт рядом со своим клиентом и проверяет запущенные программы, а играют часто на нескольких румах сразу. Режимов три:
  работать как обычно (HUD для других румов остаётся — на риск игрока, это значение по умолчанию); выключать HUD и всё,
  что работает со столами, пока клиент GG открыт; закрывать PKTracker вместе с MCP-сервером. С самой сетью GG трекер
  не взаимодействует ни в одном из режимов.
- **Панель над столом** — чёрная подложка, слева буквы вкладок на всю высоту (переключение кликом прямо за столом),
  в шапке ник и число раздач («9k»), цветной значок метки с названием типа; рамка обводит группу соседних ячеек.
- **Попап стата по наведению** (с задержкой из настроек): матрица вскрытых рук 13×13 в зелёной гамме и рядом
  диаграмма силы руки по категориям (Trash, A-high, Gutshot, Draw, Middle Pair, TPWK / TPGK, Overpair, Set, 2pair+);
  наведение на категорию показывает сами раздачи. Вкладка «Руки» — раздачи строками: карты плашками, борд по улицам,
  банк и действия буквами с размером в bb (`R3 C2 · [A 9 2] 6 · X B3.4 C3.4`), двойной клик — реплеер.
- **Реплеер проигрывает раздачу сам**: открывается после блайндов и идёт по действиям; пробел — пауза, стрелки — шаг,
  Home / End — начало и конец, скорость ×1 / ×2 / ×4; кнопка «BB» (клавиша B) показывает стеки, ставки и банк в блайндах.
  «Копировать» (Ctrl+C) кладёт в буфер обмена ход раздачи текстом или исходный текст раздачи. Панели HUD стоят снаружи от мест и не закрывают стол и журнал.
- **Аналитика** (вкладка): свои стартовые руки тепловой картой 13×13 (bb/100, сумма bb, раздач, VPIP, PFR),
  сила руки на постфлопе по улицам (чем начата улица, WTSD, выигрыш, bb/100) и графики-разрезы выигрыша
  по позиции, стеку, числу игроков, дню недели, часу и исходу раздачи. Фильтры — вид игры, позиция, стек, стол.
- **Виджет сессии** («HUD → Виджет сессии»): маленькое окно поверх столов — длительность, столы, итог в bb,
  bb/100 и график; считается только по завершённым раздачам.
- **Парная раскладка по размеру стола** («HUD → 9max / 6max по столу»): выбрана «…9max…» — на столах до 6 мест
  берётся сохранённая «…6max…» с тем же именем, и наоборот.

**Статы**
- ~130 встроенных статов, свои добавляются без программирования: условие — выражение над точкой решения или фактами руки.
- Разрезы по позиции, стеку и числу игроков задаются фильтром ячейки раскладки, а не копиями стата.
- Изменение стата пересчитывает только его, а не всю базу.

**Claude (MCP)**
- 20 инструментов: от `get_overview` и `search_hands` до `save_stat`, `set_hud_profile` и `run_sql` (только чтение).
- Анонимизация ников оппонентов включена по умолчанию.

## Установка

Нужны **.NET 10 SDK** и **PostgreSQL 17** (подойдёт портативная сборка; приложение само поднимет локальный кластер,
если положить его в `%LOCALAPPDATA%\PKTracker\pgsql` с данными в `pgdata`).

```powershell
git clone https://github.com/<ваш-аккаунт>/pktracker.git
cd pktracker
dotnet build PKTracker.sln -c Release
dotnet test tests/PKTracker.Tests          # необязательно, но полезно
.\build\publish.ps1                        # опционально: самодостаточный релиз в zip
```

Запуск — `PKTracker.bat` в корне репозитория: он сам соберёт проект, если exe нет или исходники свежее,
и поднимет трекер. Ярлык с иконкой на рабочий стол:

```powershell
.\PKTracker.bat shortcut     # ярлык «PKTracker» на рабочем столе
.\PKTracker.bat rebuild      # пересобрать и запустить
```

Иконка лежит в `src\PKTracker.App\PKTracker.ico`, перерисовывается `tools\Build-Icon.ps1`.
Напрямую exe: `src\PKTracker.App\bin\Release\net10.0-windows\PKTracker.exe`

### Первый запуск

1. **Настройки** → строка подключения к PostgreSQL, рум, папка hand history клиента.
2. **Импорт** → перетащите на вкладку папку с историей, отдельные файлы или архив (`.zip`, `.rar`, `.7z`) —
   либо выберите их кнопками. Подробности — в разделе «Загрузка раздач» ниже.
3. Дальше новые руки из папки клиента («Настройки → Папка истории раздач», флажок «Авто-импорт») подхватываются автоматически.
   **Турниры** → «Загрузить итоги»: папка с `.ots` (вместе с подпапками). Без них нет ни места, ни призовых,
   ни $EV — в hand history этого просто нет.
4. **HUD** → «Раскладка» и «Редактор HUD и попапов»; проверить оверлей без клиента можно на симуляторе
   столов (см. `CLAUDE.md`). Раскладку без GUI проверяет `hud-check` (ниже).

## Загрузка раздач

Вкладка **Импорт**. Загрузить можно тремя способами — результат один:

- **перетащить** папку, файлы или архив на вкладку;
- **«Выбрать файлы или архив…»** — файлы истории (`.txt`, `.xml`), итоги турниров (`.ots`), архивы `.zip` / `.rar` / `.7z`;
- **«Выбрать папку…»** — папка читается вместе с подпапками и лежащими в ней архивами.

Импорт начинается сразу после выбора. Архив распаковывать не нужно: он читается в память, вложенные архивы — тоже.
Уже загруженные раздачи повторно не добавляются, так что одну и ту же выгрузку можно загружать сколько угодно раз.

**Рум определяется по содержимому файла**, а не по настройке, поэтому выгрузку с несколькими румами
(например, архив Hand2Note) можно загрузить целиком. Исключение — сеть WPN: её румы по файлу неразличимы,
поэтому для таких раздач трекер один раз спросит, на каком руме сети ваш аккаунт (PokerKing, ACR, Black Chip, True Poker).

**Мои ники.** Трекер принимает только собственные раздачи — те, где вы сидели за столом (правила румов).
Ник можно не вводить заранее: клиент рума пишет карманные карты только своему игроку, поэтому владелец файлов
виден из них самих. Если такого ника нет в списке, после импорта появится вопрос «Это ваши аккаунты?» —
после ответа «Да» ники добавляются и раздачи загружаются. Вручную ник добавляется там же: ник, рум, «Добавить».

**Что не загрузится и почему** (причина пишется под полосой прогресса и во вкладке «Журнал»):

| Сообщение | Что это значит |
|---|---|
| «…раздач игрока «X» — этого ника нет в списке» | Файлы записаны клиентом игрока X. Если это вы — добавьте ник и повторите |
| «…без карманных карт игрока — это чужие раздачи» | Наблюдаемые или купленные раздачи: ни у кого нет карт. По умолчанию не принимаются (см. ниже) |
| «…сети WPN — не определить, какой это рум» | В вопросе о руме выбрано «Не мой». Добавьте ник, выбрав рум WPN, и повторите |
| «Не разобрано…» | Формат не поддержан или файл повреждён; первая ошибка приведена в сообщении |

**Раздачи без вас за столом.** Флажок «Загружать и раздачи без меня за столом» под зоной загрузки разрешает
импортировать наблюдаемые и купленные раздачи — ради статистики на оппонентов. По умолчанию он выключен:
правила большинства румов использование таких раздач запрещают. Включать или нет, решает игрок, риск — на нём.
All-in EV для таких раздач не считается, в ваши результаты и отчёты они не попадают. Под них разумно завести
отдельную базу: на тысячу раздач уходит порядка 10–15 МБ.

**Раздачи GG (GGPoker, PokerOK).** По умолчанию не импортируются: политика сети запрещает сторонним программам
импортировать и конвертировать её истории раздач, в том числе выгруженные из PokerCraft. Флажок «Загружать раздачи GG»
(в консоли — `import --gg`) включает импорт на ваш риск. Пока запущен клиент GG, её раздачи не импортируются
и с флажком; раздачи остальных румов импортируются как обычно.

### Несколько баз

Там же, в блоке **«База данных»**: список баз на сервере, **«Создать…»** (имя — латиница, цифры и `_`) и **«Удалить…»**.
Отдельная база удобна под тест, другой аккаунт или присланную выгрузку: рабочая статистика с ней не смешается.
Выбор в списке переключает трекер на другую базу; схема в новой базе создаётся сама.
Удаление необратимо, поэтому требует ввести имя базы и по умолчанию сначала сохраняет резервную копию;
удалить можно только базу трекера и только если она не единственная. Раскладки HUD и настройки от базы не зависят,
а статы, заметки и метки игроков хранятся в ней.

### Догрузка и пересчёт

Новые раздачи можно догружать в уже заполненную базу: статы по ним считаются в той же транзакции, что и запись
раздач, и итог совпадает с пересчётом с нуля (это проверяет `check-agg`). Отдельно пересчитывать базу после
догрузки не нужно.

Исключение — база, собранная прежней версией программы: новые раздачи разбираются по-новому, старые остаются
разобранными по-старому. Трекер проверяет это после каждого импорта и предлагает пересчитать базу.

Кнопка **«Пересчитать…»** в блоке «База данных»:

| Действие | Что делает | Когда нужно |
|---|---|---|
| Проверить статистику | Сверяет сохранённые итоги статов с раздачами, ничего не меняет | Есть сомнение в цифрах |
| Пересчитать статистику | Собирает итоги статов заново из уже разобранных раздач (минуты) | Проверка нашла расхождения |
| Полный пересчёт из текста раздач | Заново разбирает каждую раздачу текущей версией программы (как повторный импорт) | После обновления программы |

Во время пересчёта HUD показывает прежние цифры и переключается на новые в конце. В консоли то же самое —
`check-agg`, `rebuild` и `rebuild --full`.

```powershell
dotnet build PKTracker.sln -c Release
python tools\mcp_smoke_test.py    # проверка сервера
```

```json
{ "mcpServers": { "pktracker": { "command": "C:\\...\\src\\PKTracker.Mcp\\bin\\Release\\net10.0\\pktracker-mcp.exe" } } }
```

Claude Code подхватывает `.mcp.json` из репозитория сам. Подробности, список инструментов и настройки приватности —
в [`docs/MCP.md`](docs/MCP.md).

Примеры запросов: «найди три главных лика в моём кеше», «покажи руки, где я проиграл больше 20bb с 3-бетом из блайндов»,
«сделай стат "чек-рейз тёрна после колла сибета" и добавь в HUD», «посчитай винрейт по часам через SQL».

## Приватность и правила румов

Проект намеренно ограничен тем, что разрешают румы:

- **Только ваши раздачи.** Файл, где вас нет за столом, отклоняется целиком. Никакого датамайнинга и обмена базами.
- **Никакой подсказки в реальном времени.** Статистика считается только по завершённым раздачам.
  Live-канал клиента используется исключительно для рассадки HUD; карты и эквити текущей раздачи не читаются.
- **Claude — только после игры.** Пока запущен клиент рума, MCP-сервер не отвечает на запросы анализа (статы,
  раздачи, лики, SQL): разбор оппонентов ИИ-ассистентом во время сессии румы считают помощью в реальном времени.
  Настройка статов и раскладки HUD доступна всегда.
- **Клиент рума не трогается.** HUD — отдельные окна поверх стола: без внедрения в процесс, чтения памяти,
  снимков экрана и действий за игрока.
- **Данные остаются у вас.** Нет облачной синхронизации. В Claude уходит только то, что агент запросил в конкретном
  диалоге; ники оппонентов при этом по умолчанию заменяются псевдонимами.
- **Не публикуйте свою базу.** `.gitignore` исключает файлы истории, дампы и `settings.json` — не убирайте эти строки.

## Консоль

```powershell
$cli = "src\PKTracker.Cli\bin\Release\net10.0\PKTracker.Cli.dll"
dotnet $cli verify <папка>                  # парсинг + инварианты, без базы
dotnet $cli import --hero <ник> <папка|файл|архив>…   # другой рум: --hero WINAMAX:<ник>,IPOKER:<ник>
dotnet $cli db list                          # базы на сервере; db create <имя>, db drop <имя> --yes
dotnet $cli stats <ник> [cash|mtt]
dotnet $cli hands "Pfr && SawShowdown"      # поиск рук выражением
dotnet $cli popup <ник> cbet_flop           # содержимое попапа стата
dotnet $cli check-agg                        # агрегаты == пересчёт по normalized
dotnet $cli report [cash|mtt] [--drill <формат>]  # отчёт срезами + сверка сумм разбивок
dotnet $cli hud-check [cash|mtt] [--verbose] # прогон всех вкладок профиля HUD по игроку
dotnet $cli rebuild [--full] [--stat <код>]
dotnet $cli merge <основной ник> <старый ник>
dotnet $cli identity <папка .data>           # UUID → склейка сменивших ник
dotnet $cli watch --hero <ник> <папка>       # авто-импорт без GUI
dotnet $cli hud-import <файл.hudpack.json>   # пакет HUD: статы в базу + раскладка
dotnet $cli lab <папка> --hero <ник> --pack <пакет> [--page <вкладка|группа>]   # сверка раскладки без базы
dotnet $cli lab <папка> --hero <ник> --opp "<условие>" --hit "<условие>" --group "HPos | Spot"   # разовый стат
dotnet tools\VerifyParsers\bin\Debug\net10.0\VerifyParsers.dll <папка> [--only ROOM] [--dump <id>]
```

`lab` читает раздачи прямо из файлов (десятки тысяч рук — считаные секунды) и печатает вкладки профиля сеткой — так
определения статов сверяются с эталоном (скриншотами другого трекера) без импорта и ребилда.
`PKTracker.exe --preview <ник> [группа/вкладка]` открывает панель и попап раскладки по игроку без стола.
Третий аргумент — код стата: сразу откроется его разбор (`--preview <ник> <группа/вкладка> <код стата>`).
`PKTracker.exe --tab <вкладка>` открывает приложение на нужной вкладке (`--tab Аналитика/Графики`).
`PKTracker.exe --replay <номер раздачи>` сразу открывает раздачу в реплеере.

Автобэкап базы (pg_dump) по умолчанию пишется в «Документы\PKTracker\backups»; другая папка — поле
`BackupFolder` в `settings.json` (например, на диске, где больше места).

SDK .NET 10 может стоять не в Program Files: `PKTracker.bat` берёт его из переменной `DOTNET_ROOT`.

## Что проверено

Проверено на реальном корпусе hand history, покрывающем все поддерживаемые форматы
(кеш, MTT, SNG, спины, хедз-ап, Run It Twice, бомб-поты, мёртвая кнопка).

- **Парсер и деньги.** 0 ошибок разбора; инварианты денег и позиций зелёные на всём корпусе;
  All-in EV сохраняет банк во всех раздачах с олл-ином.
- **База.** Импорт, повторный импорт без дублей, селективный и полный ребилд, сверка агрегатов
  с пересчётом по normalized (`check-agg`), восстановление из бэкапа.
- **Раскладки.** Все 955 ячеек турнирного профиля и 655 кешевого считаются, статов с нулевым
  знаменателем нет (`hud-check`).
- **Отчёты.** Итог, все разбивки, «следующее действие», график и список рук сходятся между собой,
  и клик по строке даёт ровно её числа (`report`).
- **Попап стата.** Профит, WTSD, W$SD и доля выигранных раздач сверены с независимым пересчётом
  по базе; диапазоны по действиям складываются в общее число возможностей.
- **Прочее.** MCP-сервер по протоколу; HUD — на симуляторе столов (поиск окон, привязка, поворот,
  перекрытие). Тестов: 198.

Не проверено: **HUD на живом клиенте рума** (класс окна, формат заголовков, нумерация мест
в live-канале), **внешний вид и поведение мыши глазами** — раскладки, редактор, вкладка «Отчёты»,
попапы, наведение и перетаскивание панели правой кнопкой проверены только логикой и данными
под ними; $EV турниров на реальных `.ots`; сверка статов с другими трекерами.

## Ограничения и планы

- Активный рум («Настройки → Рум») задаёт, чьи столы показывает HUD и какую папку читает авто-импорт.
  Ручной импорт раскладывает раздачи по румам сам; авто-импорт принимает только формат активного рума.
- Кеш Winamax / GG / iPoker проверен только на синтетических раздачах; кеш 888
  и Run It Twice в 888/Winamax/iPoker пока отклоняются, анонимные столы 888 — тоже.
- ICM считается для столов до 10 игроков; для больших полей MTT $EV оценивается линейно.
- Only Hold'em: Omaha не поддерживается (в модели заложено поле варианта игры).
- Русский интерфейс; локализация не сделана.
